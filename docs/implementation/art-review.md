## Pipeline and loading contract

`tools/assets/catalog.ts` emits the immutable catalog for `prepare-prompts.py`. `compose-audio.py` authors reproducible PCM masters and SFX exports. `build-atlas.ts` runs `export-assets.py` using Python 3 and Pillow 12.1.0 (`tools/assets/requirements.txt`); ffmpeg/libmp3lame exports SFX. No generation/network operation occurs during deterministic export. The source manifest records ID/version, exact source/prompt, provenance/license, SHA256, actual dimensions, alpha, crop-safe subject bounds, foot anchor and atlas group.

Card/power/token/hero thumbnails are 256px WebP and inspect exports are 512px. All 38 UNITs, 3 tokens and 6 hero masters retain separate 512px alpha cutouts. Two quality variants share padded atlases with a maximum edge below 2048px. Hero portrait/bust/HUD/motif crops and terrain strips/icons derive deterministically from their selected masters. Inspect images are loaded lazily.

`loadBattleAssets(catalogVersion, quality)` accepts no match assignment or private state. Its fixed pool includes the selected shared atlas, **all eight terrain strips**, and the shared board scene. Browser progress/error/retry and fixed image slots preserve semantic names and rules during slow or missing art. Hero-selection banners use the approved tight HUD crops with `contain` inside their existing 80px slots so faces are never clipped; full portraits and broad busts remain available elsewhere. Retryable art is outside primary buttons; images inside primary buttons use a named fallback without nesting another button. Canvas failure retains the semantic board.

Measured pool byte counts and decoded RGBA totals, including page padding, are in [asset-budgets.json](evidence/task15/asset-budgets.json). The low pool is 1,531,376 bytes / 10,132,544 decoded RGBA bytes; the high pool is 4,045,008 bytes / 19,967,040 decoded RGBA bytes. Each includes one padded atlas page, all eight terrain strips and the shared board. The 18 exported SFX add 176,022 bytes and both PCM scores add 3,528,088 bytes when gesture-unlocked. These figures cover those explicit pools, not all browser textures, DOM images, JS, or a claim of device frame-time performance. Task 16 still owns hardware profiling and the established low-height battle-layout gate.

## Authored audio and limits

The temporary runtime oscillators have been replaced by decoded authored audio files. There are **18 distinct layered SFX families** matching Task 14's existing event mapping and **two composed eight-bar scores**: menu at 80 BPM and battle at 120 BPM. The original Python source explicitly arranges chords, melody, plucked arpeggios, bass, percussion, FM chimes, echoes and filtered material textures. These are authored offline synthesis assets, not AI-generated recordings or single-frequency audition placeholders; they use no downloaded samples, speech or third-party music.

SFX use MP3 exports; music uses exact-length stereo PCM WAV to avoid encoder-delay loop seams. [Signal inspection](evidence/task15/audio-signal.json) verifies non-silence, no clipped samples, precise score duration and loop-boundary jumps. Runtime preserves the existing settings key/schema, gesture unlock, separate music/SFX buses, menu/battle switching, pause/hidden suspension and disposal. Decode completion cannot create voices after disposal, and a rejected device resume remains unavailable.

No hardware/headphone subjective listening acceptance is claimed. Mix/timbre quality, real Safari/iOS autoplay, touch/device performance and screen-reader testing remain explicit external acceptance gates. Automated Chromium decode/playback and signal analysis do not replace those checks.
