# Durable HTTP API

Build with `pnpm build:api`. Plain Node startup is `node --env-file=.env.api.local apps/api/dist/server.mjs`; it needs Node24 and the normal API production dependencies. The distribution bundles backend workspace TypeScript and Fastify; no tsx loader, source alias or Next frontend runtime is required. `apps/api/dist/app.mjs` exports `buildApp` for a future serverless adapter; the caller must await `app.ready()` before routing requests. `server.mjs` binds `0.0.0.0:$PORT` (default3001), registers/checks the immutable release before accepting matches and closes the HTTP listener/pool on SIGTERM/SIGINT.

Supply explicit `DATABASE_URL` (restricted runtime pooler connection), `APP_ORIGIN` (one exact application origin) and `SESSION_SECRET` (cryptographically generated, at least32 characters, shared by every API instance). There is no default secret. The ignored mode0600 local HTTP env uses the existing isolated loopback test database and a separately generated server secret. Never use the migration DSN for this server. Do not commit actual env files. Browser deployment must use the same origin/proxy for `/api/v1/*`, while `/api/auth/*` remains reserved for Next managed authentication. The cookie remains Secure/HttpOnly/SameSite=Lax/Path=/ with its `__Host-` name.

Guest bootstrap takes one command UUID plus a43-character base64url256-bit recovery secret. Only recovery/session/CSRF hashes are stored. A five-minute recovery issues a fresh opaque session for the same guest and revokes the previously issued session; wrong/expired recovery, expired guest, conversion, merge markers and claim tombstones fail closed. The audit tombstone lasts seven days. Authenticated GET/session recomputes a stable HMAC CSRF token bound to the current opaque session. Authenticated mutations require that token in `X-CSRF-Token` and the exact configured Origin. Session rotation changes CSRF. This follows the session binding/header transport recommendations in the [OWASP CSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).

Private JSON uses shared strict runtime schemas, no-store and canonical serialization. Unknown input fields, stringified numeric body fields, malformed query integers and unknown query keys are rejected. Only catalog presentation DTOs are immutable-cacheable. Errors/logging omit raw exceptions, request headers/body and private checkpoint payloads. PostgreSQL shared limits enforce20 guest attempts/minute/IP HMAC,120 commands/minute/principal and10 creates/hour/principal. The default server does not trust arbitrary forwarding headers as client IP evidence; trusted deployment proxy handling belongs to the final platform adapter.

A create transaction locks the principal, checks its scoped receipt, resolves a version-pinned preset or owned saved deck, inserts immutable initialization/checkpoint/events and the validated public receipt, then commits before response. A command locks principal before match, validates its current bounded checkpoint, checks receipt before revision, applies one human intent or a bounded scheduled batch and atomically persists the new journal/checkpoint/events/result/receipt/guard metadata. An identical retry returns the same canonical response; a changed body conflicts. There is no automatic uncertain-write retry. Ordinary reads/commands do not replay the full journal; explicit diagnostic audit remains separate.

Event recovery fixes `throughSeq` to the received snapshot upper bound. Each page scans at most100 persisted rows, stops earlier at the visible quota and advances its cursor across hidden OWNER/SERVER rows. SQL projects only authorized public payloads. An empty visible page can still have `hasMore=true`. Snapshot GET has no events and does not invalidate the caller's saved log cursor. Missing/expired logs return410; detail deadlines are enforced even before cleanup deletes their rows. Owner-only summaries retain original preset or saved deck revision/opponent/difficulty/content guard after detail deletion for180 days. Account activity extends active match/receipt deadlines30 days; guests retain their absolute seven-day deadline.

Task7 deliberately supplies only engine automatic scheduling by default. Task8 must install the view-only bot scheduler before its full PvE HTTP gate. Its synchronous one-operation `Scheduler` contract lives in `matches/commands.ts`; only the service owns the eight-operation/250ms-between-roots batch loop. Human input, pause and terminal stop advancement. The durable guard travels through every step and is persisted in the same transaction; Task8 defines its per-global-turn policy. Tutorial creation currently returns VERSION_UNSUPPORTED until Task14 registers real scenario setup. GET/decks currently exposes presets with an empty saved-item list; Task9 supplies saved-deck CRUD/list routes. Provider auth/claim/logout remain Task13.

Verification includes restricted-runtime PostgreSQL HTTP integration and a separately spawned compiled Node server: a proxy consumes a committed response then drops the client connection, the server is SIGKILLed/restarted and the exact retry returns its single durable receipt. This is server durability evidence; browser store recovery, OAuth callbacks and complete both-faction PvE-to-terminal are later gates. Native Fastify handlerTimeout bounds match mutation responses to5s across routing/parsing/auth/handler work, returning canonical retryable503 TEMPORARILY_UNAVAILABLE. The transaction may still settle after that response; no timeout handler claims rollback, cancels or retries it. In-flight mutation promises remain observable and app close waits for settlement. Late results/failures cannot send another response or log raw exceptions. A real PostgreSQL row-lock test uses a shorter injected deadline, then releases the lock and verifies one committed receipt/transition is recovered by the identical retry. Request-body timeout is separately5s and PostgreSQL queries/locks remain bounded3s. Slow roots always finish atomically even when an individual root exceeds the250ms batch cut target.
