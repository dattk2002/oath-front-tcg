## Spec and quality checks

- **Usable frame and camera:** `unobscuredCardFrame` fits the playable rows inside measured screen-space blockers. The framing retains the authoritative anchors/card dimensions and full-stage canvas, and uses an off-axis camera instead of a separate DOM-only offset. Fitting includes both rows' extreme corners and hover lift. The shallow landscape corridor suppresses camera orbit while keeping card/effect motion. The new focused geometry test exercises the signature cue at five progress points and asserts all ten targets remain at least 44×44 and clear of the measured blockers.
- **Projection and picking:** Draw, DOM projection and raycast picking share the final fitted camera. Both self orientations are covered by exact-slot picker tests. The Cast button follows the actual projected cast point. Holding the camera settles card lift, preserving direct-drop alignment. No competing independent layout coordinate system was introduced.
- **Cache, observers and disposal:** The blocker/viewport key avoids repeating the empty-rectangle search when its inputs are unchanged; measurements still refresh on every scheduled draw. Resize observes the board/root, and the board mutation filter excludes the projection `style` writes and `data-projected`, avoiding a self-triggering mutation loop. Failure/disposal clears projected properties, new cast coordinates and renderer flags, disconnects both observers, removes hover/focus listeners, and retains idempotent resource/tween disposal. See the limited coverage note below regarding blocker-only reflow.
- **Hand and focus:** The scoped span reset fixes the old mulligan selector collision. Button height, fan transform and GSAP lift have separate ownership. The reduced-motion capture shows upright button/face alignment; normal-motion captures show shallow fan rotation and contained vertical costs. Horizontal scrolling is intentional; ten-card touch scrolling and keyboard arrow/Home/End reachability are covered. The 3px visible hand focus treatment and focused-seat stacking are present. The remaining viewport-resize focus issue is minor and detailed below.
- **Target size and resource legibility:** All measured field cards/slots meet the project's 44px requirement; hero-target's final cascade restores its 44px minimum after compact overrides. The phase orb and Cast button keep semantic button targets. Own hero resources are above the landscape utility disclosures, and live board stats remain within the projected control area.
- **Reduced motion and keyboard:** The landscape fan rule is now explicitly limited to `no-preference`, so it cannot override reduced-motion flattening. Existing GSAP cleanup/OS-preference handling remains. The reviewed browser run covers keyboard UNIT and NONE play with exact-once submissions, in addition to the prior approved direct-drag logic.
- **Fallback:** The full-stage board rule excludes explicit text-board mode; projection/cast properties and renderer flags are removed on failure. Existing explicit recovery, Retry 3D and semantic board controls remain. The latest courtyard ten-case run does not exercise a forced WebGL failure; this conclusion is from the changed selector/teardown paths and existing recovery code, not new browser fallback acceptance.

## Minor follow-up: retain full focused-card visibility after a viewport change

The latest `moonroot-375x812-hand5.png` shows the last card still focused after the landscape-to-portrait resize, with its right part and right focus outline clipped by the hand viewport. `Hand.tsx:104-109` scrolls the current card into view only during arrow/Home/End handling; a viewport resize does not repeat it. The existing browser assertion at `tests/e2e/courtyard.spec.ts:300` only requires some viewport intersection, which also permits this state.

This does not block the reviewed layout: focus remains visible and the hand is horizontally scrollable, so this is not a finding of fully obscured focus or a WCAG AA failure. For complete focus containment, re-scroll the focused hand card after the hand viewport changes, retaining the fan/focus gutters. Add a narrow regression that focuses the last card, switches from landscape to portrait, and checks the focused button plus its focus allowance against the hand's visible bounds. Avoid claiming that every focus outline is always unclipped until that case is addressed.

## Coverage note, not a reproduced defect

`scene.ts:841-858` observes board/root size and board subtree mutations, while the measured blockers include sibling hero and motion controls. A blocker-only size/content change that leaves the board/root box unchanged is not itself an invalidation source; its updated rectangle is incorporated on the next scheduled draw. The reviewed fixed-size/resizing cases and active cue paths are covered, and no current stale-frame overlap was reproduced. A narrow reduced-motion/idle case that changes a HUD block's height would establish whether additional blocker ResizeObserver targets are needed. Do not treat speculative failure here as a reason for another broad test run.
