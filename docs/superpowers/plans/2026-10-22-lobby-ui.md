# Lobby UI Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement these tasks sequentially.

**Goal:** Apply the user's seven screenshot corrections to the account, hero selection, power badges and deck presentation, exclusively in the frontend.

**Architecture:** Reuse the catalog and existing match/deck/auth clients. A compact account disclosure replaces the persistent banner. Hero selection becomes a viewport-sized lobby with paginated equal-size cards and Play inside the profile; Play selects the existing preset and opens the existing opponent confirmation. Deck cards show their actual contents rather than an oversized chart.

**Tech Stack:** Existing Next.js/React, CSS tokens, SVG, GSAP. No new dependencies. React Bits Tilted Card and Animated List inform interaction; GSAP remains the motion engine.

**Spec:** Latest user request and screenshots; existing `docs/design/elements-visual-contract.md` and frozen Pen contract. The choices below are implementation decisions, not new game rules.

## Global constraints

- Do not edit API, database, contracts, content catalogs, deck rules or auth behavior.
- Preserve Pen typography/palette and existing uncommitted audio/auth work; work in the already authorized main checkout.
- All visible copy remains English. Preserve all hero names in full.
- Desktop 1024×640 and above: no document scrolling in hero selection. Page the roster instead of clipping it. Mobile/tablet must retain readable controls; zoom/short landscape may scroll as an accessibility fallback.
- Six heroes per roster page on desktop; four on compact screens. Every tile has the same reserved selected-status row. Selected hero remains in view when crossing breakpoints.
- Play opens the existing opponent/difficulty confirmation with the selected hero's preset; Browse decks retains access to saved/custom decks.
- Motion only transforms/opacity, scoped cleanup, interrupted selection safe, reduced motion static. No CSS keyframe choreography.
- No redesign of the battle board in this task.

## Review focus

- Long names such as Brimstone/Gravemarch must remain whole and visible.
- Selection, paging and viewport changes must not move focus into hidden elements or change a chosen hero unexpectedly.
- Account restoration and urgent auth messages must remain accessible while the banner is collapsed.
- Deck card count and quantities must reflect preset/saved entries; unknown historical cards must not silently disappear.
- Rapid switching, hidden tabs, missing images and reduced motion must leave the UI usable.

## Design plan

The approved game/Pen language overrides generic AIDA, font replacement and randomized page composition. Keep Barlow Condensed, ink/paper/lilac/acid tokens, character art and the two-part roster/profile. Typography uses shrinkable containers and whole names; selection slots are reserved. The profile's actions are inside its frame. Deck previews prioritize cards over statistics. Navigation, controls and target outlines retain contrast. GSAP uses short entrance staggers and bounded pointer depth; no scrolling effects in the viewport lobby.
